# Screendance App 1.7.0 — development record

Status (November 1, 2026): implemented in source on branch `screendance/v1.7.0`
(on top of the 1.6.0 commit `b8e14f11`). **Not built, signed, notarized or
published.** Version in `package.json` is 1.7.0.

## Features and where they live

| Feature | Key files | Notes |
| --- | --- | --- |
| Source thumbnails | `electron/native/ScreenCaptureKitWindowList.swift` (`--thumbnails` mode), `electron/ipc/register/sources.ts` (`get-source-thumbnails`), `electron/ipc/sourceThumbnails.ts`, `src/components/launch/SourceSelector.tsx` | macOS lists windows natively and never had thumbnails; previews are now fetched lazily via `SCScreenshotManager` (macOS 14+), JPEG data URLs, cached 2.5 s, own app excluded by pid. Selection compares source ids (`isSourceSelected`). |
| Change capture while paused | `ScreenCaptureKitRecorder.swift` (`switch_source`, `set_microphone` stdin commands), `electron/ipc/recording/macLiveControl.ts`, IPC `switch-native-screen-recording-source` / `set-native-screen-recording-microphone` in `electron/ipc/register/recording.ts`, `useScreenRecorder.liveCapture`, HUD `pausedCaptureControls` in `LaunchWindow.tsx` | Paused native macOS recordings only. The output resolution stays fixed; a new source is letterboxed via `SCStreamConfiguration.destinationRect` and the helper returns the normalized content viewport. Main stores it in `state.cursorContentViewport`, applied by `applyCursorContentViewport` so cursor telemetry stays aligned. Mic: muting writes zeroed samples (continuous track), enabling mid-take creates the `.mic.m4a` sidecar on the video time base, device change uses `updateConfiguration`. Browser mic fallback can only mute/unmute. |
| Webcam on/off/device while paused | `src/hooks/liveWebcamCompositor.ts`, `useScreenRecorder` (`attachWebcamRecorder`, `createWebcamCompositorStream`, `setWebcamWhilePaused`) | On macOS the webcam MediaRecorder records a canvas compositor, so the camera can be released, re-acquired or swapped. Off spans are tracked by `HiddenRangeTracker` (recording time, pauses excluded) and travel as `webcamHiddenRanges` in the recording session/manifest into `webcam.hiddenRanges`. A webcam first enabled mid-take uses `timeOffsetMs` = recorded time and is hidden before it. |
| Webcam hidden ranges in the editor | `shared/timeRanges.ts`, `VideoPlayback.applyWebcamBubbleLayout`, `frameRenderer.drawWebcamOverlay`, `modernFrameRenderer.updateWebcamOverlay`, `modernVideoExporter` (`unsupported-webcam-hidden-ranges` forces the JS renderer) | Never carried by presets (`mergeEditorPresetWebcamSettings`, preference normalization). Cleared when webcam media is replaced/removed. |
| Content-anchored highlights | `types.ts` (`type: "highlight"`, `HighlightData`), `videoPlayback/contentHighlights.ts`, `ContentHighlightEditor.tsx`, `AnnotationSettingsPanel.tsx` (Highlight tab), both frame renderers, `projectPersistence.ts`, `shared/editorAutomation.ts` | For highlights `position`/`size` are **percentages of the full source frame** (like cursor telemetry), projected through `maskRect.sourceCrop`. Drawn as Pixi `Graphics` inside the camera container (below the cursor) in preview and both export renderers; the DOM editing layer copies the camera transform. Screen-space annotation paths skip them. 120 ms fade at both ends. |
| Last background for new recordings | `editorPreferences.resolveFreshRecordingWallpaper`, `VideoEditor.rememberWallpaperChoice`, `applyLastSelectedPresetToFreshVideo` | `preferences.wallpaper` is now written only on explicit choices (background panel, applying a preset), no longer by the auto-save effect, so opening an old project does not change it. Fresh recordings/imports apply the last preset and then the remembered wallpaper. |
| HUD hit-zone fix | `LaunchWindow.tsx`, `electron/windows.ts` (`hud-overlay-hide`) | The stationary wrapper (`p-2`) was `pointer-events-auto`; after the bar was translated during a recording drag, its old footprint kept switching mouse passthrough off. Now only the bar and webcam preview are interactive. Hiding restores passthrough before minimizing. |
| CLI/MCP `recording.adjust` | `shared/automation.ts`, `cli/commands.ts`, `useRecorderAutomation.ts` | 85 commands. `screendance recording adjust --source ID --microphone true --webcam-device ID` while paused. |

Native helper binaries (`recordly-window-list`, `recordly-screencapturekit-helper`)
were rebuilt for `darwin-arm64` and `darwin-x64` (macOS 14 target) with plain
`swiftc -O -target …`; the other helpers are unchanged. A release build must
still run `npm run build:mac` (rebuilds all helpers, signs, notarizes).

## Verification done

- `npx tsc --noEmit` clean; `npx vitest run`: all suites pass (new tests for
  thumbnails ids, source selection, fresh wallpaper, highlight geometry/drawing/
  persistence, time ranges, hidden-range tracker, live-command bridge, cursor
  viewport).
- Real ScreenCaptureKit run inside the dev Electron (existing screen grant), two
  generated fixture windows (680×420 blue, 900×400 orange), helper driven
  directly: record A → pause → `switch_source` B → resume → pause → back to A →
  resume → stop. Output 1360×840, 6.05 s (pauses excluded). Frame at 3 s: B
  centered with black bars (viewport y=0.140, h=0.719); at 1 s and 4.9 s: A full
  frame. `switch_source` while not paused is refused. `--thumbnails` returned
  JPEG previews for both windows.

### Full-app checks on November 1, 2026 (dev Electron, isolated profiles)

- `recording.adjust` via CLI against the running app: A → B (letterboxed) → A
  confirmed by frame colors; cursor telemetry written.
- Microphone muted mid-take via CLI and via the paused HUD menu: muted span is
  exact digital silence (-inf dB), unmuted spans keep room noise (~-65 dB); the
  sidecar stays continuous and aligned (8.19 s vs 8.15 s video).
- HUD UI: source grid with live screen/window thumbnails; paused HUD shows
  source/mic/webcam pickers; switching to another window from the HUD shows a
  "Recording source switched" toast and the take continues with the new window;
  the bar can be dragged during recording and stays interactive.
- Found and fixed during these checks: thumbnail helper deadlock (top-level
  `Task` waiting on a blocked main thread), parallel ScreenCaptureKit helpers
  deadlocking each other (now serialized in main), thumbnails not refreshing on
  reopen, `recording.stop` failing with `EDITOR_NOT_OPEN` when the editor window
  had not opened yet, and a new highlight being invisible at its own start time.

### Installed-app checks on November 2, 2026 (signed 1.7.0, isolated profile)

A local arm64 build (`npm run build:mac -- --arm64 --dir`, G2 signed via
`afterSign`, **not notarized**) replaced `/Applications/Screendance App.app`
(1.5.0) at the owner's request; the previous app is kept at
`release/backup-installed-1.5.0/Screendance App.app`. The designated requirement
(`dev.screendance.app` + team `BN3D9H4C7J`) is unchanged, so the existing TCC
grants (screen, microphone, camera, accessibility) applied. Tests ran with
`SCREENDANCE_USER_DATA_DIR` pointing at `.tmp/app-check/profile` (directories
must be mode 700 for the automation API), launched via `open -n -a … --env`.

- Webcam turned on mid-take and off again via `recording adjust`: webcam file
  starts at `timeOffsetMs` 2765, frames are black after it was turned off, and
  the session/editor carry `hiddenRanges` [0–2765] and [5987–8714].
- Microphone off/on mid-take: exact silence only in the muted span, aligned.
- Highlights: marker and rectangle draw in the live preview, follow a 1.8×
  zoom, and appear in an exported MP4; webcam appears/hides by range in export.
- Background: after opening an old project with a red background, a fresh
  recording used the last explicitly chosen wallpaper (Midnight 8).
- HUD hit zone (real mouse, full-screen control): after dragging the bar up
  during a recording, clicks at its old position reached the window below
  (centre and both edges); the moved bar stayed clickable when hovered.
- Testing notes: plain `pkill` leaves the app alive long enough that a new
  instance loses the single-instance lock and looks hung — use `pkill -9`;
  `--remote-debugging-port` also stalled startup. A click that jumps the cursor
  onto the HUD without a preceding hover can pass through (mouse passthrough is
  toggled on hover); real pointer movement works.
