# Screendance App 1.6.0 — local automation upgrade

Validation date: October 25, 2026. This version has not been published to GitHub
or installed over the user's existing application. The scope is all six stages
of the CLI/MCP automation plan; see [coverage](../automation/coverage.md).

## Behavior

- 84 typed commands share one registry across CLI and MCP. Recording reuses the
  full microphone/webcam/cursor finalization pipeline; saved projects use explicit
  paths and atomic writes.
- Full document edits, atomic batches, presets, automatic zooms, playback and
  complete undo/redo share the editor's state and history. Revision checks include
  manual UI edits; document identity guards stale work after renderer reloads.
- Export, captions and model downloads run as application-owned durable jobs.
  Disconnecting MCP leaves a job running. Restart marks unfinished jobs interrupted;
  retry is explicit. Export freezes document/settings/media references at enqueue,
  publishes atomically and retains a finished artifact if publication fails.
- The editor's Jobs footer exposes progress, cancellation, retry and saving a
  retained export. Known errors are localized in English/Russian; cancelled jobs
  and successfully rescued outputs no longer show misleading error warnings.
- The packaged universal `Contents/MacOS/screendance` launcher runs the CLI using
  the application's Electron runtime. Separate Node.js is unnecessary for users.
  `install` creates only a user-local CLI link; `setup codex|claude` prints the
  registration command without editing another application's configuration.

## Related fixes

Per-clip source audio gain, mute and normalization now follow source/output time
through trims, speed changes and chunks. Selection no longer changes exported
sound. Custom motion values and caption fonts survive project reopening; applying
generated captions enables display and refuses to replace a changed document.
Extension replacement is transactional, and marketplace archives, output targets
and log reads have bounded path/identity checks.

## Reproduce

```sh
npm test
npx tsc --noEmit
node --test scripts/macos-code-components.test.mjs scripts/macos-g2-signing.test.mjs scripts/sign-macos-g2.test.mjs
npm run build:automation
npm run smoke:automation
node scripts/smoke-automation-upgrade.mjs
APPLE_KEYCHAIN_PROFILE=GZB-notary npm run build:mac -- --config.directories.output=release/notarized-v1.6.0-automation
```

Builds require the G2 Developer ID certificate/private key already in Keychain,
Xcode tools and architecture-matching native dependencies. A clean Whisper runtime
build also needs CMake; this Mac reused the existing matching arm64/x64 Whisper
artifacts because CMake was unavailable. No private credentials are stored here.

## Validation limits

The caption smoke uses real audio extraction with a deliberately fake local speech
runtime. Recognition quality and a new model download were not exercised. Remote
marketplace installation has mocked network/archive tests, not a production catalog
purchase/install. Physical microphone/webcam hardware, the full permission matrix,
and macOS 14 on physical Intel hardware require manual validation. The x64 packaged
check on this Apple Silicon Mac uses Rosetta. Update installation and external
publication were not performed.
