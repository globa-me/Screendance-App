# Screendance App 1.5.0 — release validation

Published 23 September 2026 at
https://github.com/globa-me/Screendance-App/releases/tag/v1.5.0.

## User-facing changes

- The separate source picker opens correctly. Missing thumbnails show a clear
  source-type icon, and VoiceOver announces long names once.
- Russian is selectable in both language menus. The locale check now verifies
  configuration, runtime registration, menu labels and JSON structure.
- Wallpaper choices, editor sections and the timeline playhead have visible
  keyboard focus. The playhead supports Left/Right, Shift+Left/Right (5 s),
  Home and End. Editor Tab navigation no longer gets intercepted.
- Deleted presets and custom wallpapers can be restored from an Undo toast.
- The export menu shows common controls first and puts encoding, FPS and engine
  settings under Advanced. Small labels and switches are easier to use.
- Export asks where to save before rendering and checks destination write
  access and estimated free space. Progress is visible from the toolbar even
  if the settings popover closes. Cancellation waits for the export process to
  stop before confirming it. Direct saves replace output files atomically.
- WebM-to-ProRes conversion explicitly sets BT.709 color space metadata.
- Recording permission and source errors appear as localized, nonblocking
  notifications.

## Developer handoff

- The UX audit and initial evidence are in
  `docs/audits/2026-09-23-ux-ui/README.md`.
- Destination preflight is registered in `electron/ipc/register/export.ts` as
  `select-export-destination`, exposed through `electron/preload.ts`, and called
  before `handleExport` starts rendering in `VideoEditor.tsx`.
- Export state and pending Save Again data remain in renderer memory. A future
  main-process export-job journal is needed for recovery after a renderer or
  app crash. The preflight uses an estimate, so disk capacity may still change
  during rendering.
- ProRes vendor, codec and pixel format remain unchanged. BT.709 settings were
  added to the WebM-to-ProRes conversion path. The Quick Look guardrail in
  `AGENTS.md` still applies to later changes.

## Notarized release artifacts — 23 September 2026

The `Screendance-notary` Keychain profile is active. A previous `notarytool`
exit 69 was transient; a new history request succeeded and the full dual build
ran with `APPLE_KEYCHAIN_PROFILE=Screendance-notary`. Apple accepted and
electron-builder stapled both apps before creating their ZIP and DMG packages.
App submissions: arm64 `561c0759-4b3e-4225-82e6-b428db05ea3e`, x64
`4e3783ae-c39e-49ce-bf29-e13c81d813b5`. DMG submissions: arm64
`91e23c0f-97a1-48a0-aae7-3a71d6fe4293`, x64
`31d8e335-534a-4562-a485-bb87aa94028a`. All four were `Accepted`.

The final files are in `release/notarized-v1.5.0/`. Both DMGs were stapled.
`scripts/finalize-macos-release.mjs` passed strict app/DMG signatures,
stapler validation and Gatekeeper assessment with `source=Notarized Developer
ID`, then refreshed blockmaps, `latest-mac.yml` and `SHA256SUMS.txt`.
`hdiutil verify`, checksum verification and packaged-binary smoke passed for
each architecture. Both final DMGs were mounted read-only; their contained
apps passed deep/strict signature verification, stapler validation and
Gatekeeper assessment. The smoke tool must receive one app root at a time:

```sh
PACKAGED_SMOKE_ROOT=release/notarized-v1.5.0/mac-arm64 PACKAGED_SMOKE_ARCH_TAGS=darwin-arm64 npm run smoke:packaged-binaries
PACKAGED_SMOKE_ROOT=release/notarized-v1.5.0/mac PACKAGED_SMOKE_ARCH_TAGS=darwin-x64 npm run smoke:packaged-binaries
```

The first smoke invocation against the common release root checked both app
bundles with the same architecture tag and failed at the opposite bundle's
`uiohook` check. The per-app invocations above passed. The signed staging
directory remains historical; distribute files from `release/notarized-v1.5.0/`
after publication. A clean, quarantined first launch and a physical Intel Mac
test remain manual release checks.

  folder, set `com.apple.quarantine`, and launched it through Launch Services.
  App Translocation was active. Gatekeeper accepted it as `Notarized Developer
  ID`; the HUD and editor opened without a crash.
- The HUD identified version 1.5.0 and exposed Russian in its language menu.
  After source enumeration finished, the primary screen and available windows
  appeared, and the primary screen could be selected.
- Imported a generated three-second MP4, inspected its editor preview, and
  exported a low-resolution MP4 through the new destination picker. `ffprobe`
  confirmed H.264 video at 648×1152, AAC audio and a 3.0-second duration.
- Recorded the primary display with microphone disabled, stopped recording,
  and opened the result in the editor. `ffprobe` confirmed a 13.08-second
  H.264 file at 3024×1964. No media or export errors appeared in the app log.
- The test recording was moved out of the user's recordings folder into the
  temporary smoke directory. The test projects were closed without saving.
- Repeated `npx tsc --noEmit`, `npm test` (76 files, 670 tests),
  `npm run i18n:check` and `git diff --check`; all passed.

A physical Intel Mac was unavailable. The x64 package passed notarization,
